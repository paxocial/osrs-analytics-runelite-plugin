# Repository Guidelines

## Project Structure & Module Organization
- Core plugin code lives in `src/main/java/com/cortalabs/osrs/analytics/`; web calls are under `.../web`, UI panels/overlays in `.../panel` and `.../ui`, and shared helpers in `.../util`.
- RuneLite descriptor and config assets sit in `src/main/resources/com/cortalabs/osrs/analytics/`; the plugin entry is `runelite-plugin.properties` pointing to `com.cortalabs.osrs.analytics.AnalyticsPlugin`.
- Tests and the launch harness live in `src/test/java/com/cortalabs/osrs/analytics/AnalyticsPluginTest.java`.
- Assets are in `img/`, `flags/`, and `flags/` masks are generated by `scripts/mask-images.sh`. Build outputs land in `build/`.

## Build, Test, and Development Commands
- `./gradlew clean build` — compile, run annotation processing (Lombok), and emit the plugin jar plus `build/resources/main/version.ini`.
- `./gradlew test` — execute JUnit 4 tests (currently minimal harness).
- For manual dev runs, use `AnalyticsPluginTest` as a launcher inside RuneLite; ensure RuneLite client dependency resolves from `https://repo.runelite.net`.

## Coding Style & Naming Conventions
- Java 8, UTF-8, tabs for indentation (match existing files), and prefer final/immutable collections (`ImmutableList`, etc.).
- Keep RuneLite patterns: `@PluginDescriptor` metadata, `@Subscribe` for events, constructor injection via Guice.
- Use Lombok where already present (`@Slf4j`, `@Getter`); avoid adding new frameworks without need.
- Name configs and menu entries descriptively; keep text user-facing strings short and RuneLite-friendly.

## Testing Guidelines
- Add JUnit tests beside new code in `src/test/java/...`; name classes with `*Test`.
- For behavioral changes, include a manual verification note (steps + expected RuneLite behavior) in the PR.
- If you touch HTTP flows, stub external calls where possible; avoid hitting production endpoints in tests.

## Commit & Pull Request Guidelines
- Commits: short, imperative summaries (e.g., “Refactor clan sync menu options”). Keep related changes together; avoid noisy reformatting.
- PRs: describe intent, key changes, manual test notes, and screenshots/GIFs for UI tweaks. Link issues/tasks when applicable.

## Rebrand & Endpoint Updates
- Target domain is `cortalabs.com` (API at `osrs.cortalabs.com/api`). Base hosts now live in `src/main/java/com/cortalabs/osrs/analytics/web/AnalyticsClient.java` and UI links; keep them aligned with backend routes.
- Metadata is under `runelite-plugin.properties` (displayName, author, support URL, tags, description) and Gradle (`settings.gradle`, `build.gradle`). Package references now use `com.cortalabs.osrs.analytics`.
- Keep licensing intact (BSD 2-Clause in `LICENSE`); retain attribution in headers when modifying borrowed files.

## Security & Configuration Tips
- Do not log API tokens or player identifiers beyond what RuneLite already exposes. Scrub sensitive data before telemetry.
- Gate any new metrics that touch private data (bank/collection log) behind explicit config flags with clear labels.
